# 입수 패키지 작성 규칙 — 모바일 디스패치 + Claude Code 흐름

박준호가 다른 Claude 챗 세션에서 "입수해줘" 트리거를 사용했을 때 받게 되는 **입수 패키지의 표준 형식**. 이 페이지는 그 패키지를 생성하는 모든 Claude 세션이 지켜야 할 절대 규칙.

---

## 1. 박준호의 실제 작업 흐름

```
[핸드폰 클로드 챗] → 입수 패키지 받음
        ↓ 복사 (한 번)
[핸드폰 디스패치] → PC 원격 제어
        ↓ 붙여넣기 (한 번)
[PC Claude Code] → vault 보고 자동 분배·생성·갱신·git push
```

핵심 제약:
- 박준호가 PC 앞에 없음 (모바일 디스패치 사용)
- 모바일 환경에서 박준호 추가 입력·왔다갔다 작업 부담 큼
- **한 번의 붙여넣기 + 짧은 명령으로 모든 작업이 끝나야 함**

박준호 자기 진술 (출처: [[원본/대화/2026-05-15_입수패키지_작성규칙-운영규칙]]):

> "최대한 작업방식이 간단명료하고 시간을 뺏지 않았으면 좋겠어 여러번 일 안하고 한번의 명령으로 처리될수있게 말이야"

---

## 2. 입수 패키지 작성 절대 원칙 4가지

### 2.1 한 덩어리 마크다운 (절대)
- 블록 여러 개로 나누지 않음
- 코드블록 중첩으로 박준호 혼란 주지 않음
- 박준호 복사 1회 = 모든 내용 포함

### 2.2 자기완결적 (Self-contained)
- 입수 패키지 안에 Claude Code가 작업할 모든 정보 포함
- 박준호 추가 설명·추가 명령 없이도 Claude Code가 처리 가능
- 박준호 후속 명령은 "위키에 반영해줘" 한 줄이면 끝

### 2.3 Claude Code가 판단 가능한 구조
- frontmatter로 메타데이터 명시
- 영향받을 페이지 명시
- 색인·로그 갱신안 한 줄씩 포함
- Claude Code가 박준호 vault 구조 + 입수 패키지 정보로 분배 판단 가능

### 2.4 박준호 작업 부담 0
- 박준호가 폴더 만들기·파일명 결정·위치 판단 X
- 박준호는 복사 → 붙여넣기 → 짧은 명령 한 번

---

## 3. 모바일 디스패치 환경 추가 고려사항

- 박준호가 디스패치 통해 PC 화면 보면서 작업하지만, **모바일에서 텍스트 입력은 느림**
- 따라서 박준호가 Claude Code에 추가로 타이핑할 내용은 최소화
- 입수 패키지 자체에 "이걸 위키에 반영해줘"라는 의도가 frontmatter나 구조로 드러나야 함
- 박준호가 "위키에 반영해줘" 정도만 타이핑하면 끝나는 구조

---

## 4. 표준 입수 패키지 구조

다음 섹션들을 **한 마크다운 안에 순서대로** 포함:

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | frontmatter | 일자, 종류, 주제, 태그 |
| 2 | 제목 | 대화 핵심 한 줄 |
| 3 | 박준호 자기 진술 원문 | 다듬지 않고 그대로 |
| 4 | 대화 흐름 요약 | 시간순 또는 논리순 짧게 |
| 5 | 핵심 발견·결정 | 이번 대화의 결정적 내용 |
| 6 | 박준호 자기 시스템 작동 사례 | 해당 시 |
| 7 | 영향받을 위키 페이지 | 갱신 후보 + 신규 후보 |
| 8 | 색인 갱신안 | 한 줄 |
| 9 | 로그 갱신안 | 한 줄 |
| 10 | 다음 대화 보강 권장 | 선택 |

## 5. 박준호의 작업 흐름 (단순화된 최종 형태)

박준호의 입수 작업 = 다음 4단계로 끝:

1. 클로드 챗에서 입수 패키지 받음
2. 마크다운 전체 복사 (한 번)
3. 디스패치로 PC Claude Code 창에 붙여넣기
4. "위키에 반영해줘" 짧은 명령 입력

이후 Claude Code가 자동 처리:
- 새 파일 생성
- 기존 파일 갱신
- 색인·로그 업데이트
- git add + commit + push

→ **박준호는 4단계 이후 작업 없음**

---

## 6. 향후 클로드 챗 세션이 지킬 절대 규칙

박준호가 "입수해줘" / "위키에 저장" / "이거 위키에 넣어" 트리거 사용 시:

### 6.1 반드시 해야 할 것
- 한 덩어리 마크다운으로 작성 (단일 코드블록)
- frontmatter 포함
- 박준호 자기 진술 원문 보존
- 영향받을 페이지 + 색인·로그 갱신안 명시
- 코드블록 안에 또 다른 코드블록 중첩하지 않음 (박준호 복사 혼란 방지)

### 6.2 절대 하지 말 것
- 여러 블록으로 나누기
- 박준호에게 폴더·파일명 결정 요구
- 박준호에게 "어디에 붙여넣으세요" 안내
- 박준호가 손으로 분배해야 하는 형태로 제공
- 박준호 추가 입력·확인·왔다갔다 요구

## 7. 예외 상황

박준호가 명시적으로 다른 방식을 요청하는 경우에만 예외:
- "손으로 정리할 거니까 블록 나눠줘"
- "PC에서 직접 작업할 거야"
- 기타 박준호 명시 요청

**기본은 항상 한 덩어리 마크다운**.

## 8. Claude Code 측의 처리 (본 vault 세션)

이 페이지는 입수 패키지를 **만드는 쪽** 규칙. 입수 패키지를 **받아서 처리하는 쪽** (Claude Code) 의 작동 원칙:

1. 패키지의 frontmatter·구조 읽고 분배 판단
2. 본 vault의 카테고리·페이지 구조에 맞춰 정합 정정 (예: 페르소나 세션의 `사업/` → 본 vault의 `주제/`)
3. 페르소나 세션이 가정한 페이지명 오타 자동 정정 (이전 입수에서 확인된 패턴)
4. 원본 보존 → 위키 페이지 신설/갱신 → 색인·로그 → git commit & push
5. 박준호에게 마지막에 한 번만 짧게 보고

이 처리 원칙은 [[위키/운영/위키의_본질]] 의 클로드 위키 활용·기억 원칙과 같은 뿌리.
