# 입수 패키지 작성 규칙 — 모바일 디스패치 + Claude Code 흐름

박준호가 다른 Claude 챗 세션에서 "입수해줘" 트리거를 사용했을 때 받게 되는 **입수 패키지의 표준 형식**. 이 페이지는 그 패키지를 생성하는 모든 Claude 세션이 지켜야 할 절대 규칙.

---

## 1. 박준호의 실제 작업 흐름

```
[핸드폰 클로드 챗] → 입수 패키지 받음
        ↓ 복사 (한 번)
[핸드폰 디스패치] → PC 원격 제어
        ↓ 붙여넣기 (한 번)
[PC Claude Code] → vault 보고 자동 분배·생성·갱신·git push
```

핵심 제약:
- 박준호가 PC 앞에 없음 (모바일 디스패치 사용)
- 모바일 환경에서 박준호 추가 입력·왔다갔다 작업 부담 큼
- **한 번의 붙여넣기 + 짧은 명령으로 모든 작업이 끝나야 함**

박준호 자기 진술 (출처: [[원본/대화/2026-05-15_입수패키지_작성규칙-운영규칙]]):

> "최대한 작업방식이 간단명료하고 시간을 뺏지 않았으면 좋겠어 여러번 일 안하고 한번의 명령으로 처리될수있게 말이야"

---

## 2. 입수 패키지 작성 절대 원칙 4가지

### 2.1 한 덩어리 마크다운 (절대)

- 블록 여러 개로 나누지 않음
- 코드블록 중첩으로 박준호 혼란 주지 않음
- 박준호 복사 1회 = 모든 내용 포함

### 2.2 자기완결적 (Self-contained)

- 입수 패키지 안에 Claude Code가 작업할 모든 정보 포함
- 박준호 추가 설명·추가 명령 없이도 Claude Code가 처리 가능
- 박준호 후속 명령은 "위키에 반영해줘" 한 줄이면 끝

### 2.3 Claude Code가 판단 가능한 구조

- frontmatter로 메타데이터 명시
- 영향받을 페이지 명시
- 색인·로그 갱신안 한 줄씩 포함
- Claude Code가 박준호 vault 구조 + 입수 패키지 정보로 분배 판단 가능

### 2.4 박준호 작업 부담 0

- 박준호가 폴더 만들기·파일명 결정·위치 판단 X
- 박준호는 복사 → 붙여넣기 → 짧은 명령 한 번

---

## 3. 모바일 디스패치 환경 추가 고려사항

- 박준호가 디스패치 통해 PC 화면 보면서 작업하지만, **모바일에서 텍스트 입력은 느림**
- 따라서 박준호가 Claude Code에 추가로 타이핑할 내용은 최소화
- 입수 패키지 자체에 "이걸 위키에 반영해줘"라는 의도가 frontmatter나 구조로 드러나야 함
- 박준호가 "위키에 반영해줘" 정도만 타이핑하면 끝나는 구조

---

## 4. 표준 입수 패키지 구조

다음 섹션들을 **한 마크다운 안에 순서대로** 포함:

| 순서 | 섹션 | 내용 |
|---|---|---|
| 1 | frontmatter | 일자, 종류, 주제, 태그 |
| 2 | 제목 | 대화 핵심 한 줄 |
| 3 | 박준호 자기 진술 원문 | 다듬지 않고 그대로 |
| 4 | 대화 흐름 요약 | 시간순 또는 논리순 짧게 |
| 5 | 핵심 발견·결정 | 이번 대화의 결정적 내용 |
| 6 | 박준호 자기 시스템 작동 사례 | 해당 시 |
| 7 | 영향받을 위키 페이지 | 갱신 후보 + 신규 후보 |
| 8 | 색인 갱신안 | 한 줄 |
| 9 | 로그 갱신안 | 한 줄 |
| 10 | 다음 대화 보강 권장 | 선택 |

## 5. 박준호의 작업 흐름 (단순화된 최종 형태)

박준호의 입수 작업 = 다음 4단계로 끝:

1. 클로드 챗에서 입수 패키지 받음
2. 마크다운 전체 복사 (한 번)
3. 디스패치로 PC Claude Code 창에 붙여넣기
4. "위키에 반영해줘" 짧은 명령 입력

이후 Claude Code가 자동 처리:
- 새 파일 생성
- 기존 파일 갱신
- 색인·로그 업데이트
- git add + commit + push

→ **박준호는 4단계 이후 작업 없음**

---

## 6. 향후 클로드 챗 세션이 지킬 절대 규칙

박준호가 "입수해줘" / "위키에 저장" / "이거 위키에 넣어" 트리거 사용 시:

### 6.1 반드시 해야 할 것

- 한 덩어리 마크다운으로 작성 (단일 코드블록)
- frontmatter 포함
- 박준호 자기 진술 원문 보존
- 영향받을 페이지 + 색인·로그 갱신안 명시
- 코드블록 안에 또 다른 코드블록 중첩하지 않음 (박준호 복사 혼란 방지)

### 6.2 절대 하지 말 것

- 여러 블록으로 나누기
- 박준호에게 폴더·파일명 결정 요구
- 박준호에게 "어디에 붙여넣으세요" 안내
- 박준호가 손으로 분배해야 하는 형태로 제공
- 박준호 추가 입력·확인·왔다갔다 요구

---

## 7. 예외 상황

박준호가 명시적으로 다른 방식을 요청하는 경우에만 예외:
- "손으로 정리할 거니까 블록 나눠줘"
- "PC에서 직접 작업할 거야"
- 기타 박준호 명시 요청

**기본은 항상 한 덩어리 마크다운**.

---

## 8. Claude Code 측의 처리 (본 vault 세션)

이 페이지는 입수 패키지를 **만드는 쪽** 규칙. 입수 패키지를 **받아서 처리하는 쪽** (Claude Code) 의 작동 원칙:

1. 패키지의 frontmatter·구조 읽고 분배 판단
2. 본 vault의 카테고리·페이지 구조에 맞춰 정합 정정 (예: 페르소나 세션의 `사업/` → 본 vault의 `주제/`)
3. 페르소나 세션이 가정한 페이지명 오타 자동 정정 (이전 입수에서 확인된 패턴)
4. 원본 보존 → 위키 페이지 신설/갱신 → 색인·로그 → git commit & push
5. 박준호에게 마지막에 한 번만 짧게 보고

이 처리 원칙은 [[위키/운영/위키의_본질]] 의 클로드 위키 활용·기억 원칙과 같은 뿌리.

## 9.5 위반 사례 및 강화 규칙 (2026-05-20 신설)

본 규칙이 정립된 후 첫 위반 사이클이 2026-05-20에 발생했고, 박준호의 즉시 지적으로 강화 규칙이 추가됨. 모든 향후 클로드 챗 세션이 따라야 할 절대 규칙.

(출처: [[원본/대화/2026-05-20_헤르메스AI에이전트구상_입수규칙강화]])

### 9.5.1 위반 사건 기록

**1차 위반**:
- 클로드 출력 형태: 입수 패키지를 *별도 마크다운 섹션·코드블록 산발 배치*로 출력
- 위반된 규칙: 2.1 (한 덩어리 마크다운), 2.4 (박준호 작업 부담 0)

**2차 위반**:
- 박준호 1차 지적 후 클로드 재출력: 단일 코드블록으로 작성했으나, 코드블록 *위쪽 사과·설명문* + *아래쪽 사용 안내문* 부가
- 위반된 규칙: 2.1의 정신 (박준호 복사 경계가 흐려지면 한 덩어리의 의도 깨짐)
- 박준호 지적: *"바로 옵시디언에 바로 한번에 붙여넣을수있게 블록만들어서 쓰라고 했는데 나누지 말고"*

**3차 미비**:
- 박준호 추가 요청: *"이 블록을 만들때 코드에 내가 입수해줘라고 입력하지 않아도 되게끔 블록 안에 입수하라는 명령도 같이 있으면 좋겠어"*
- 미비 내용: Claude Code 자기실행 명령 누락 → 박준호가 "위키에 반영해줘" 직접 타이핑 필요

### 9.5.2 위반의 근본 원인

- 클로드가 본 *입수 패키지 작성 규칙* 페이지를 입수 요청 받기 *전*에 미리 확인하지 않음
- 답변 형식 기본값(섹션 나눠 설명형)이 입수 패키지 형식(한 덩어리)을 덮음
- 코드블록 외부에 부가 텍스트를 붙이는 습관이 박준호의 복사 행동을 고려하지 않은 결과
- 입수 패키지가 박준호의 추가 타이핑을 전제로 작성됨 — 모바일 디스패치 환경의 진짜 무게를 반영하지 못함

### 9.5.3 강화 규칙 — 작성 전 절대 확인 단계 (NEW)

박준호의 입수 트리거를 받으면, 패키지 작성 *시작 전*에 다음 3단계를 반드시 수행:

1. **본 규칙 페이지 즉시 조회** (project_knowledge_search 등 도구로)
2. **박준호 vault 실제 폴더 구조 확인** — `위키/자아/`·`위키/생각/`·`위키/주제/`·`위키/사람들/`·`위키/사건/`·`위키/시기/`·`위키/장소/`·`위키/질문/`·`위키/운영/`·`위키/AI/`·`위키/지식/` (2026-05-20 기준)
3. 그 다음 패키지 작성 시작

### 9.5.4 강화 규칙 — 출력 형식 절대 규칙 (NEW)

1. **단일 코드블록 안에 입수 패키지 전체 포함** — 4-backtick 권장 (본문에 3-backtick 인용이 있어도 깨지지 않음)
2. **코드블록 위·아래에 부가 텍스트 절대 X** — 인사·사과·설명·사용 안내 일체 없음. 출력은 코드블록 하나만.
3. 코드블록 내부에 또 다른 4-backtick 코드블록 중첩 X (본문 코드 인용은 3-backtick만)
4. 박준호가 코드블록 우상단 복사 버튼 한 번 누르면 = 전체 입수 패키지 = 한 번에 PC Claude Code로 이동 가능

### 9.5.5 강화 규칙 — Claude Code 자기실행 명령 절대 포함 (NEW)

입수 패키지 **frontmatter 바로 다음에** *Claude Code 실행 지시* 섹션을 박는다. 박준호가 PC Claude Code 창에 붙여넣은 직후, **추가 명령 입력 없이** Claude Code가 자동으로:
- 원본 보존판 저장
- 신규 페이지 생성 / 기존 페이지 갱신
- 색인·로그 갱신
- git commit & push
- 박준호에게 짧은 완료 보고

→ 박준호의 모바일 디스패치 추가 타이핑 = **0**. 박준호 자기 진술 *"한번의 명령으로 처리될수있게"* 의 최종 형태.

### 9.5.6 갱신된 표준 패키지 구조 (11항 — 이전 10항에서 자기실행 명령 추가)

1. frontmatter (일자, 종류, 주제, 태그, **트리거 발언**)
2. **Claude Code 실행 지시** (NEW — frontmatter 바로 다음, 박준호 추가 타이핑 0 보장)
3. 제목
4. 박준호 자기 진술 원문 (다듬지 않음)
5. 대화 흐름 요약
6. 핵심 발견·결정
7. 박준호 자기 시스템 작동 사례 (해당 시)
8. 영향받을 위키 페이지 (신규 후보 + 기존 갱신 후보)
9. 색인 갱신안
10. 로그 갱신안
11. 보강 권장 (선택)

→ 2번 항목 *Claude Code 실행 지시* 섹션 누락 = 박준호가 "위키에 반영해줘" 직접 타이핑 필요. 절대 누락 X.

### 9.5.7 갱신된 절대 하지 말 것 (8항)

- 입수 패키지를 여러 블록으로 나누기
- 코드블록 외부에 부가 텍스트 붙이기 (위·아래 모두)
- 박준호에게 폴더·파일명·위치 결정 요구
- 박준호에게 "어디에 붙여넣으세요" 안내
- 박준호가 손으로 분배해야 하는 형태로 제공
- 박준호 추가 입력·확인·왔다갔다 요구
- **입수 트리거 받고 본 규칙 페이지 확인 없이 작성 시작** (NEW)
- ***Claude Code 실행 지시* 섹션 누락** (NEW — 빠지면 박준호 추가 타이핑 발생)

### 9.5.8 박준호 자기 시스템 작동 사례 — 규칙 강화 패턴

박준호의 *청개구리식 인지 전환* 원문 *"보류나 여지를 남기지 않으려고 해 가능한"* — 본 대화에서 1차 위반 즉시 지적 → 2차 위반 즉시 재지적 → 3차 미비 즉시 추가 요구. **보류 없이 정확성·완결성 추구**. 박준호의 *시스템 빌더* 결정 패턴이 위반 사례 자체를 *위키에 박아넣는 메타인지 시스템 자원*으로 전환 ([[위키/자아/변신로봇_시스템빌더_징검다리]]).
